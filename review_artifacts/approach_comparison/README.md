# Decision-policy candidates and ledgers

These files preserve all three experiments on the same participant evidence and genuine cached AI interpretations. They are derived predictions/diagnostics, not provider response caches and not inputs to prediction logic.

Each split contains strict_auditor.csv, conservative_fallback.csv and evidence_prediction.csv, with corresponding case ledgers and a measured usage summary. The JSON ledgers distinguish eligible source states, model-interpreted media, scope deductions, unresolved records, assumptions and inferred states. They retain case IDs and exact citations without inventing resource IDs or historical events.

**Do not submit conservative_fallback.csv:** its unsupported INCOMPLETE fallback labels lack the required findings/remediation/verification plan. It is intentionally retained so its invalid rows can be measured. The strict CSV is partial. The full evidence_prediction.csv is the518-row candidate also published as root output.csv. Root output.assumptions.json binds the published CSV by SHA256 and preserves its99case assumption ledger and measured usage.

File/schema validity is separate from evidence entailment. One restore-risk finding is a forecast from known archive existence, not proven current authorization. Added COMPLETE conclusions depend on discovered evidence bounding the relevant inventory. These assumptions remain unresolved; zero novel resource IDs does not mean zero unsupported claims. Confirmed exclusions are applied only in evaluation, never in these prediction policies.

Read code/evaluation/approach_comparison.md and approach_comparison_metrics.json for coverage, row validity, label distributions, phase checks, unsupported claims, affected cases, public accuracy and recommendation. Recompute with `code/compare_approaches.py` followed by `code/evaluation/compare_approaches.py`. The evaluator requires genuine local context for its independent support checks; it never uses public answers to generate a candidate.

The current extracted-archive validation is in archive_verification.json; the older review_artifacts/archive_verification.json remains a historical strict-baseline snapshot. All comparison model work is offline; cached extraction attribution is shared across policies and is not summed three times. Paid API budget:$0.
